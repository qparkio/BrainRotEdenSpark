# Agent installation and first run

Use this guide to set up **Steal my Brainrot** from source and connect a coding agent to the EdenSpark editor.

**Project author: andruw ([qparkio](https://github.com/qparkio)).**

## 1. Identify the project

This is a native **EdenSpark / Gen2 Daslang** game. The client entry point is `main.das`; the lobby's dedicated-server process runs `dedicated.das`. Runtime models, textures, materials, fonts, and audio are included in `assets/`.

Read [README.md](README.md), [the development guide](docs/DEVELOPMENT.md), and [validation notes](docs/VALIDATION.md) before changing the project. A normal checkout does not require regenerating any assets.

## 2. Prepare the environment

These instructions target Windows, the environment used for this project's recorded checks.

| Requirement | Purpose |
| --- | --- |
| [EdenSpark](https://edenspark.io/en), installed and started once | Launcher, editor, compiler, and game runtime |
| Git | Clone and update the source checkout |
| A coding agent with local file access | Inspect and edit the checkout |
| HTTP MCP support in the agent | Inspect the live editor, logs, scene, and screenshots |
| Python 3 with `venv` support, optional | Run static asset validation and asset tools |

Blender, Node.js, and FFmpeg are optional asset-authoring tools. They are not prerequisites for launching the included game. Install applications from their official sources and use the engine already installed on the machine where possible.

## 3. Obtain the source

If the repository is already checked out, inspect `git status` and `git remote -v` and continue from that directory. Preserve local changes.

For a fresh checkout, run the following in PowerShell. The default projects library is under the user's Documents folder; use the actual launcher library if it was moved.

```powershell
$projectsDir = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'My Games\eden\launcher\projects'
if (-not (Test-Path -LiteralPath $projectsDir -PathType Container)) {
    throw 'Start EdenSpark once, or set projectsDir to the existing launcher projects library.'
}

$repoDir = Join-Path $projectsDir 'BrainRotEdenSpark'
if (Test-Path -LiteralPath $repoDir) {
    throw 'The target already exists. Inspect the existing checkout instead of overwriting it.'
}

git clone https://github.com/qparkio/BrainRotEdenSpark.git $repoDir
if ($LASTEXITCODE -ne 0) {
    throw 'Clone failed. Resolve the Git error before continuing.'
}
Set-Location -LiteralPath $repoDir
```

Verify that `manifest.blk`, `main.das`, `dedicated.das`, `main.prefab`, and `assets/` exist. Keep all shipped `.meta` files: they contain resource GUIDs and import settings. The manifest's `defaultPrefab` is the GUID from `main.prefab.meta`, not a filesystem path.

If another copy of this game is already installed, check its project identity before opening both copies. A copied directory retains the same `project_guid`; copying files alone does not create an isolated test profile.

## 4. Open the editor and connect MCP

1. Open the project from the EdenSpark launcher and choose **Edit**. The editor must be running; the launcher alone does not provide the editor's MCP server.
2. Open this same checkout as the coding agent's workspace. Confirm that the editor is showing **Steal my Brainrot** from that directory before issuing scene or runtime commands.
3. Use the local MCP configuration generated by EdenSpark when available. Those machine-specific integration files are intentionally excluded from this public repository.
4. If no connection is configured, run `app.mcp_status` in the editor console to inspect the MCP server and registered tools. Configure the agent's HTTP MCP connection using the port reported by the editor.

For clients that use `.mcp.json`, the connection shape is:

```json
{
  "mcpServers": {
    "EdenSpark": {
      "type": "http",
      "url": "http://localhost:54300/mcp"
    }
  }
}
```

`54300` is an example from the local setup; replace it if the editor reports a different port. Other clients may use a different configuration format. Keep this endpoint local and leave the generated connection files untracked.

Use one editor instance for MCP control. For a multiplayer check, use an additional game client; do not assume that two editors can share one control port.

Discover the connected server's tools, then read the active project's compilation status and recent logs. A successful HTTP connection does not by itself establish that the intended game is open or running.

## 5. Look up engine APIs before editing

Use the EdenSpark MCP server's `search_docs` tool for EdenSpark and Daslang APIs. If its documentation index is unavailable, use the installation's bundled documentation and samples:

```powershell
$engineRoot = Join-Path $env:LOCALAPPDATA 'EdenSpark'
$docsDir = Join-Path $engineRoot 'docs'
$samplesDir = Join-Path $engineRoot 'samples'
```

Use the actual installation directory if EdenSpark was installed elsewhere. Useful bundled references include `docs/source/getting_started/start_here.rst`, `docs/source/getting_started/vibecoding.rst`, `docs/source/getting_started/console_commands.rst`, and `docs/source/index/networking.rst`.

Scripts use **Gen2** syntax: braces for functions and blocks, parentheses for conditions, and `elif` for alternate branches. Keep new tunables in `constants.das`, shared mutable state in the state modules, and per-entity behavior in Components. Load resources during initialization. Keep client/server entry hooks in their entry files and preserve resource GUIDs when changing assets. See [the module map](docs/DEVELOPMENT.md#runtime-layout).

## 6. Run the optional static asset check

From the repository root, with a Windows Python installation that provides the `py` launcher:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/requirements.txt
.\.venv\Scripts\python.exe tools/qa/validate_assets.py
```

If Python is exposed as `python` instead, use `python -m venv .venv` for the first command. If `.venv` already exists, inspect and reuse it rather than recreating it blindly. Calling its Python executable directly avoids changing PowerShell execution policy.

Expected result: **56 unique GLBs**, matching bounds and feet, **79 unclipped thumbnails**, three UI atlases, three world-texture import settings, and the EdenSpark logo pass validation. The generated `tools/qa/asset_validation.json` is ignored by Git.

This result verifies asset structure. It does not prove that the game compiles, launches, renders correctly, or supports a multiplayer session.

## 7. Perform a bounded runtime smoke check

1. Save the source and wait for compilation to finish. Inspect the current compiler output and fresh logs; resolve errors before continuing.
2. If the game is stopped, press the editor's **Play** button. If it is paused, resume it. Wait for initialization before using lobby or scene tools.
3. In the game's menu, press **PLAY**, then choose **Play locally** in the lobby. The lobby starts the dedicated server and connects the client.
4. Confirm that the player and arena have appeared. Inspect the actual player/item replicas, current logs, and a fresh screenshot; a network-connected status alone is insufficient.
5. Check movement, camera rotation, the Index, and a normal interaction. Record what was actually observed.
6. If multiplayer behavior is part of the requested change, join the same room with a second client and check the relevant action from both clients.

Report static checks, compilation, runtime behavior, networking, and visual evidence separately. If the editor or MCP connection is unavailable, state that runtime verification is unavailable; do not turn a static pass into a gameplay claim. The [existing validation notes](docs/VALIDATION.md) distinguish historical two-client results from current checks.

## 8. Isolate destructive tests and preserve project ownership

- Before testing profile resets, money/item fixtures, sales, rebirths, or destructive progression scenarios, create a disposable project with its own `project_guid` and storage namespace. The shipped server uses `brainrot-profiles-v1` in both `load_storage` and `save_storage`; isolate both calls in the disposable copy.
- Keep `DEBUG_CHEATS = false` in the published game. Do not run destructive fixtures against the owner's normal save.
- Review the exact files staged for a commit. Keep local MCP settings, caches, saves, logs, environments, and credentials out of Git.
- Preserve andruw's project attribution and the [third-party asset notices](docs/ASSETS.md). Do not add coding tools as authors or coauthors. Installation does not require changing Git identity or global Git settings.
- Commit, push, or submit a game build only when the current user request authorizes that action. Setting up an agent does not authorize a new platform submission or publishing unrelated files.

## Troubleshooting

| Symptom | Next check |
| --- | --- |
| MCP is disconnected | Keep the editor open; check `app.mcp_status`, its port, and the local agent configuration. |
| MCP is connected to the wrong game | Match the editor's project directory with the agent workspace before issuing commands. |
| The lobby connects but the arena/player is incomplete | Wait for initialization, inspect fresh logs and replicated player/item nodes, then capture the actual scene. |
| An asynchronous operation appears stuck while paused | Resume the game before judging callbacks initiated by game code. |
| Assets are missing or show the wrong import settings | Restore the paired `.meta` files and preserve their GUIDs; rerun the asset checker. |
| The Python checker fails to import a package | Install `tools/requirements.txt` into the interpreter used to run the checker. |
| A fresh checkout seems to have existing progress | Check the project GUID and storage namespace before changing or resetting anything. |
